## Обоснование разделов для проверочного листа

1. Управление доступом

- Существуют два типа команд: функциональные и операционные. Внутри функциональной команды есть разные типы ролей: владелец продукта, бизнес аналитик, разрабтчик, инженер по эксплуатации, DevOps инженер. Необходимо обеспечить предоставление каждой роли только необходимых для работы доступов.
- Со стороны систем обработки данных нет ограничений на доступ к данным.
- Некоторые контракты позволяют внешним пользователям выполнять действия и получать данные, к которым у них не должно быть доступа (Например, партнёр из одной управляющей компании может увидеть или изменить данные клиентов и жилищных комплексов, которые относятся к другой компании).

2. Безопасность данных

- Ограничения по передаваемым данным в основном обусловлены бизнес-процессами между взаимодействующими IT-продуктами.
- Системы используют API управляющих компаний без единых политик по безопасности и без системного контроля за передаваемыми данными.
  - компания собирается активно развивать сервисы для покупателей и жильцов. В том числе — за счёт партнёрских сервисов.
  - Контракты API содержат категории данных, которые явно предоставляют персональные данные.
- Клиенты в личном кабинете иногда могут видеть данные других клиентов.
- Проблема управления и хранения потоков данных блокирует реализацию новых продуктов, основанных на данных.
- У бизнеса есть потребность: проверить соответствие требованиям законодательства
- Есть несколько точек регистрации нового клиента, координации между этими точками нет.
- Внутренние потоки данных между IT-продуктами контролируются не системно.

3. Защита инфраструктуры

- У бизнеса есть потребность: проверить соответствие требованиям законодательства
- У бизнеса есть потребность: реагировать на инциденты

4. Управление инцидентами

- Недавно у конкурента произошла утечка данных
- У бизнеса есть потребность: реагировать на инциденты

5. Специфические аспекты
6. Управление оборудованием и физической безопасностью
   - Большинство IT-продуктов развёрнуты на собственных серверах
   - Сервисы компании развёрнуты в приватном облаке, имеется собственный ЦОД и используются мощности, арендованные у облачного провайдера
7. Управление облачной инфраструктурой
   - Сервисы компании развёрнуты в приватном облаке и используются мощности, арендованные у облачного провайдера
   - Часть продуктов развёрнуты в гибриде
